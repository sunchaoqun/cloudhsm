AWS CloudHSM 集成方案

一套 Spring Boot 应用，四种密钥后端，统一密码服务

AWS KMS KMS Custom Key Store CloudHSM JCE CloudHSM PKCS#11

签名 / 验签 · 加密 / 解密 · 对称 + 非对称 · 跨账号

01方案目标

用同一套接口，演示 CloudHSM 的多种接入方式与密码能力

  • 四种后端：AWS KMS、KMS Custom Key Store（对接 CloudHSM）、CloudHSM JCE、CloudHSM PKCS#11
  • 统一接口：Controller 只依赖一个 CryptoService，切换后端只需换启动 profile，接口与前端不变
  • 完整密码能力：RSA 签名/验签、AES 对称加解密、RSA 非对称加解密
  • 跨账号：一个账号的应用，调用另一个账号 CloudHSM 里的密钥
  • 可视化演示：内置网页，点按钮即可演示，顶部显示当前后端与调用账号

02整体架构

前端 → REST → 统一接口 → 按 profile 选择后端实现 → 密钥运算在 HSM/KMS 内完成

演示网页→ REST /api/*→ CryptoService（统一接口）→ 四选一后端实现

kms

AWS SDK v2，纯 Java，托管 KMS key

kms-cks

KMS Custom Key Store，运算落到 CloudHSM 集群

jce

CloudHSM JCE Provider，直连 HSM

pkcs11

JDK SunPKCS11 + CloudHSM .so

前端按后端上报的 capabilities 动态显示可用操作，不支持的自动隐藏。

03四种后端能力对比

后端签名/验签对称加解密非对称加解密密钥位置
KMS（通用）✔✔✔AWS 托管
KMS Custom Key Store✘✔✘CloudHSM（仅对称）
CloudHSM JCE✔✔✔HSM 硬件
CloudHSM PKCS#11✔✔✔HSM 硬件

关键结论：KMS Custom Key Store 只支持对称密钥，不能做签名/非对称（官方限制）。 要用 CloudHSM 做签名/非对称，走 JCE 或 PKCS#11。

04KMS 与跨账号访问

KMS Custom Key Store

KMS 的 key 建在你的 CloudHSM 集群里，加解密运算在 HSM 硬件内完成，调用方用标准 KMS API，无感知。

对称加解密不支持签名

跨账号（已验证）

账号 A 的应用调用账号 B 的 CloudHSM key：
① Key 侧 Key Policy 放行账号 A
② 账号 A 侧 IAM 授权用该 key
两道授权都满足即可，加解密实测通过。

页面顶部实时显示当前调用的 AWS Account，跨账号演示一目了然。

05CloudHSM JCE Provider

AWS 官方推荐的 Java 接入方式，功能最完整

  • 通过 CloudHSM 自家 JCE Provider 直连 HSM，密钥运算全部在硬件内完成，私钥永不出 HSM
  • 完整支持：RSA 签名/验签、AES-GCM 加解密、RSA-OAEP 非对称加解密
  • 认证用 HSM 的 Crypto User 账号密码（非 AWS 凭证）
  • 密钥按 label 引用；单 HSM 场景需关闭 key availability check

✔ 四项密码操作全部验证通过

06CloudHSM PKCS#11（标准接口）

行业标准 PKCS#11，跨 HSM 厂商可移植；本方案用 JDK 内置 SunPKCS11 对接

  • 对称（AES）：走标准 KeyStore，用 AES-CBC（SunPKCS11 与 CloudHSM 都稳定支持传入 IV）
  • 非对称（RSA 签名/验签/加解密）：CloudHSM 不在 HSM 存证书，SunPKCS11 的 KeyStore 因此看不到 RSA 私钥
  • 解决：绕开 KeyStore，用底层 PKCS#11 按 label 直接定位 key 再包装成 JCA 密钥（不依赖证书）

✔ 签名/验签、AES、RSA 非对称 全部打通

注：Java 用 SunPKCS11 对接 CloudHSM 做 RSA 属社区方案；官方 Java 首选 JCE。

07关键难点与解法

现象根因解法
KMS-CKS 不能签名Custom Key Store 只支持对称密钥签名走 JCE / PKCS#11
AES-GCM 解密失败IV 由 HSM 在加密时生成，须先 doFinal 再取 IV调整取 IV 时序，IV 前缀入密文
PKCS#11 找不到 RSA 私钥CloudHSM 不存证书，SunPKCS11 靠证书配对底层按 label 定位 key，绕开证书
PKCS#11 RSA-OAEP 报错SunPKCS11 不认该 padding 写法改用 RSA PKCS#1 padding
PKCS#11 AES-GCM init 失败SunPKCS11 要 IV / CloudHSM 不让传 IV，冲突PKCS#11 改用 AES-CBC

08CloudHSM 集群安装与初始化

从创建集群到激活可用，五步（区域以 ap-southeast-1 为例）

① 创建集群

控制台 → Create Cluster，选 VPC 与可用区（VPC/子网创建后不可改）。建好后把集群的 Security Group 加到 EC2 安全组，放通访问。

② 建首个 HSM + 下载 CSR

点 Initialize → 选子网建第一个 HSM 实例 → 向导提供 Cluster CSR 下载。

③ 签发证书并上传

用自建 CA 给 CSR 签名，得到 Cluster 证书 + Issuing 证书（customerCA.crt），上传后 Upload & Initialize。

④ 装 CLI + 激活

EC2 装 cloudhsm-cli，拷 customerCA.crt 到 /opt/cloudhsm/etc/，configure-cli -a <HSM_IP> → cluster activate 设管理员密码。

⑤ 建 crypto-user

admin 登录后 user create --username <user> --role crypto-user，应用即可用该用户连接集群做密码操作。

09关键命令速查

签发证书 → 装 CLI → 激活 → 建用户

# 1) 生成客户 CA（私钥务必妥善保管）
openssl genrsa -aes256 -out customerCA.key 2048
openssl req -new -x509 -days 3652 -key customerCA.key -out customerCA.crt

# 2) 用 CA 签集群 CSR（<CLUSTER_ID> 换成你的）
openssl x509 -req -days 3652 -in <CLUSTER_ID>_ClusterCsr.csr \
  -CA customerCA.crt -CAkey customerCA.key -CAcreateserial \
  -out <CLUSTER_ID>_CustomerHsmCertificate.crt

# 3) EC2 装 CLI + 配置信任锚与 HSM IP
sudo yum install ./cloudhsm-cli-latest.el7.x86_64.rpm
sudo cp customerCA.crt /opt/cloudhsm/etc/customerCA.crt
sudo /opt/cloudhsm/bin/configure-cli -a <HSM_IP>

# 4) 激活集群 + 建 crypto-user
/opt/cloudhsm/bin/cloudhsm-cli interactive
aws-cloudhsm > cluster activate
aws-cloudhsm > login --username admin --role admin
aws-cloudhsm > user create --username <user> --role crypto-user

10现场演示

同一网页，切换 profile 即切换后端；按钮按能力自动显隐

# 通用 KMS
--spring.profiles.active=kms

# KMS Custom Key Store（对接 CloudHSM，仅对称）
--spring.profiles.active=kms-cks

# CloudHSM JCE（HSM 硬件，全功能）
--spring.profiles.active=jce

# CloudHSM PKCS#11（标准接口，全功能）
--spring.profiles.active=pkcs11

页面：① 签名/验签   ② 对称加解密   ③ 非对称加解密（RSA）
